# Project brief
Last updated: 2026-11-22. Public at github.com/VinayNarne/whiteboard-tutor; the lesson board is the only tutor (the older raw-SVG tutor was retired on 2026-11-21), on gpt-4.1-mini.

## Goal
A one-on-one AI whiteboard tutor: it speaks and draws on an SVG board while explaining; the learner asks by chat or voice. Built for one local learner. Phase 2 (notebook memory beyond the foundations) has NOT started.

## Stack and setup
FastAPI + SQLModel (Postgres, SQLite fallback), React/Vite, Azure OpenAI (now `gpt-4.1-mini`), ElevenLabs TTS (timed to the drawings), Deepgram voice input.
Backend on port 8100; `frontend/.env.local` needs `VITE_BACKEND_PORT=8100`. `.env` endpoint must be `https://<resource>.openai.azure.com/` WITHOUT `/openai/v1` (that suffix gives a 404).

## Frozen
- System prompt and tool text (digests pinned in `tests/test_prompt_rules.py`). Tool RESULT texts (notes, rejection messages) are not frozen; wording changes need approval first.
- Founding rule: constrain how the agent records its work, never what it chooses to draw. No code that guesses or repairs what the model meant.

## Parked
- Features taken from a competing product and built: faster first output, draw_graph, formulas, Today's path, welcome back, Explain/Simpler/Example/Ask on a board item, a following camera with captions, pause and speed. Left out on purpose: AI-painted illustrations, forgiving voice input, a voice mood per line. Not built yet: a replay that jumps to any turn (ours replays a page from the start).
- Further summary eval beyond eval M. A true per-attempt model ceiling. Any other Phase 2 work. (Reasons and triggers: `docs/PHASE2_FOUNDATIONS.md`.)
- Learner controls, from lesson tests (2026-11-19): undo and redo for the learner's pen and highlighter on the board; pause, resume, faster and slower for the tutor's drawing and voice. Nice to have; the tutor's teaching comes first.
- Two ideas from the 2026-11-17 research (Code2Video, video_explainer, TheoremExplainAgent; read, not run). Build after further lesson tests, icons first:
  - Icons in diagrams. One open-source icon package (Lucide, ISC, about 1,500 icons; or Tabler, MIT), installed, not thousands of files in git. The tutor writes a plain word on a box (`icon: "sun"`); the code matches it to icon names and tags. No match: the box has no icon and the tutor is told which word failed. The label always stays (the icon only supports it); a short alias list fixes words with two meanings ("mouse"). No AI-made icons (uneven, clashes with the hand-drawn style). Abstract ideas get no icon, by design.
  - Teach from the learner's PDF or notes. Digital PDFs first with `pypdf` (BSD): good text, multi-column order and tables can come out loose, scans give nothing. A page with almost no text is a scan: say so clearly at first; later render it with `pypdfium2` (Apache/BSD) and let the cheap vision deployment read it (cents per document). Docling (MIT) if complex layouts need it. Avoid PyMuPDF (AGPL) and Marker (GPL). Cost rule: read once on upload, store in sections, send only the 2-3 relevant sections per turn; cap uploads at about 30 pages. The lesson check's fact judge can then check replies against the document.
  - Maybe later, after icons: 3D drawings with Zpup (github.com/rxolve/zpup, MIT, TypeScript, no dependencies, 26 KB gzipped; JSON scene in, plain SVG out). Only for the few topics that need depth (Earth's tilt, orbits, molecules, volume of solids), as one block where the tutor names the solids and our code places them; the model must not set 3D coordinates (code says where). Young (v0.3, API may change), so wait for 1.0. Skip Zdog (its ancestor): unmaintained since 2022 and draws shapes in the wrong order. Idea to borrow sooner: Zpup's error style, all problems at once, each with where it is and a "did you mean" fix, for the tutor's refused-board messages.
  - Not taken: Manim/Remotion videos (minutes to render, not interactive). Worth adding to the lesson check only: a vision model that looks at the finished board for overlaps, clipping and ugly layout.

## Decisions made
- Model switched from gpt-4.1-mini to gpt-4.1: all baselines in `docs/BASELINE.md` are mini and do NOT carry over; a new baseline is needed.
- Text-width hint is log-only. Lost-content note capped at 2 per element per turn; it tells the model to write the character itself. Failed turns, empty replies, a 90 s model-call ceiling and a 60 s read timeout exist.
- A result counts only if all runs are outside the reference run-to-run range. Before blaming the model, compare raw output with what was stored and read the HTTP status.
- p5.brush (2026-11-13): was a proof only, OFF by default (`LP_PAINT=1`; commit 39eee98, `PaintLayer.tsx`); the proof code was archived 2026-11-21 (removed from the repo, kept in old_version/). It paints watercolour and pencil texture under the SVG board from recipes stored in the SVG, so zoom stays sharp and replays match. Why not further: it adds looks, not new kinds of drawings (SVG can already draw any shape) and little teaching value; costs a second renderer, GPU speed unknown, dark theme and PNG export unfinished. Kept on for everyone: `draw_graph` shading (plain SVG). Revisit if learners find the board plain (next step: a "Watercolour style" toggle in View). SVG-only alternative built the same day (`LP_PAINT=svg`): chart shading as Rough.js pencil hatching (looks like p5.brush, pure SVG, exports), node watercolour as an SVG filter (ragged edge, mottling; weaker than p5.brush, rim reads grey, zoom about 114 vs 66 ms per step with it, off on the dark theme, not in exports). If a textured look is wanted later: SVG hatching yes; watercolour still open. Textures are NOT an agent capability: the tutor decides what to show (`shade` on a graph), the look is the app's style, never the model's choice.
- Shaders / Shadertoy (2026-11-08, parked): shaders do not help text, diagrams or speed. Possible later: a "live simulation" block (waves, particles, heat, colour map of a function) from presets WE write and test in plain WebGL2; the tutor only picks a preset and its settings, never writes shader code (ShaderMatch, LLM4Code 2025: models fail 31% on 467 Shadertoy shaders; shader compilers are a browser attack surface, DarthShader CCS 2024). Shadertoy code is CC BY-NC-SA 3.0 (non-commercial) unless its author says otherwise: learn from it, do not copy it into the product. Do not use LYGIA (non-commercial licence).
